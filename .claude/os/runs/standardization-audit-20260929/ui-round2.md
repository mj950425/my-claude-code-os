# 작업 화면 표준화 감사 — UI Round 2

- 기준일: 2026-09-29
- 평가자: Luna (독립 UI 재평가)
- 범위: 홈, 공통 내비게이션, 다섯 등록 작업의 정책·골든셋 화면, 지원되는 네 작업의 증분 검수 화면
- 평가: 공통 구조·탐색 25, 목적/허용값/규칙 25, 전체 정책·SDK 투영 표시 20, 링크·폼·상태 20, 읽기 쉬움·반응형 10
- 보호: SDK 호출, DB 연결, 사람 판정 원장 기록은 하지 않았다. 저장 동작은 테스트의 임시 fixture만 사용했다.

## 점수

지원되는 GT 작업은 작업 전용 화면과 네 작업이 공유하는 증분 화면 점수의 평균으로 산출했다. 작업 전용 화면만 지원하는 정책 과제는 그 정책 화면으로 점수화했다. 계산 결과가 .5이면 높은 정수로 반올림했다.

| 작업 | 작업 전용 화면 | 공유 증분 화면 | 최종 UI | 결과 |
|---|---:|---:|---:|---|
| `accessories-category-gender` | 97 | 95 | **96** | 통과 |
| `bag-category-gender` | 98 | 95 | **97** | 통과 |
| `clothing-category-gender` | 99 | 95 | **97** | 통과 |
| `clothing-thumbnail-observation` | 98 | 95 | **97** | 통과 |
| `clothing-thumbnail-model-gender` | 98 | 해당 없음 — 정책 전용 | **98** | 통과 |

작업 전용 화면의 항목별 점수(공통 구조·탐색 / 목적·값·규칙 / 전체 정책·SDK 표시 / 링크·폼·상태 / 읽기·반응형)는 다음과 같다.

| 작업 | 점수 구성 |
|---|---|
| `accessories-category-gender` | 25 / 25 / 20 / 18 / 9 = 97 |
| `bag-category-gender` | 25 / 25 / 20 / 19 / 9 = 98 |
| `clothing-category-gender` | 25 / 25 / 20 / 20 / 9 = 99 |
| `clothing-thumbnail-observation` | 25 / 25 / 20 / 19 / 9 = 98 |
| `clothing-thumbnail-model-gender` | 25 / 25 / 20 / 19 / 9 = 98 |
| 공유 증분 검수 화면 | 25 / 23 / 18 / 20 / 9 = 95 |

다섯 작업 모두 90점 이상이며, 차단 항목은 없다. 9/10의 반응형 점수는 좁은 화면 CSS는 확인했지만 이번 라운드에서 실제 모바일 뷰포트를 따로 검사하지 않은 점을 반영한다.

## Round 1 결함 수정 및 재확인

### UI-1 — 준비 전 과제에서 끊기던 골든셋 검수 링크

GT 기능이 있는 작업의 공통 사이드바 검수 링크를 서버의 준비 상태 라우트 `/gt/<task>`로 연결했다. `clothing-category-gender`는 준비 전 상태여서 이 라우트가 404 대신 홈의 해당 과제 카드로 돌려보내고, 카드에는 `준비 전`과 준비 요청 문구가 보인다. 이 과제 상태는 기능 누락으로 채점하지 않았다.

### UI-2 — 정책 전용 작업의 없는 검수·골든셋 링크

과제 프로필의 `gtTask` 지원 여부를 사이드바에 전달한다. `clothing-thumbnail-model-gender`처럼 정책만 지원하는 화면에는 검수·골든셋을 링크처럼 가장하지 않고, 두 항목을 비활성 텍스트 `이 작업은 제공하지 않음`으로 표시한다. `/gt-tasks`에서 이 작업은 정책 항목으로만 나오고 GT 작업 목록에는 없으며 `/incr-tasks`에도 없다. 정책 링크는 계속 열 수 있다.

### UI-3 — 증분 화면에서 잘못된 작업으로 가던 정책·골든셋 메뉴

증분 화면 URL의 `?task=` 값을 공통 사이드바의 현재 작업으로 사용한다. 브라우저에서 `/incr?task=clothing-category-gender`를 열어 확인한 결과, 부모 `정책` 링크는 `/f/clothing-category-gender/gt-review/policy.html`, `골든셋` 링크는 같은 작업의 `golden.html`을 가리킨다. 두 메뉴를 눌러도 활성 과제가 유지된다.

## 실행 근거

- `.claude/os/engine/scripts/gt_review.py pages --task <task>`로 제공되는 작업별 정책/골든셋 화면을 다시 그렸다. 정책 전용 모델 성별 과제에는 정책 화면만 생성된다. 문서 검토 후 `clothing-thumbnail-observation` 페이지도 최종 정의와 링크 표를 읽어 재생성했다. 준비된 GT의 `review.html`은 `render_current(record=False)`로 갱신해 asked/blind-history 원장 기록을 건너뛰었다.
- `incr_render.py`로 증분 화면을 다시 만들었고 `--check` 결과 `같습니다`였다.
- 생성된 `.claude/os/runs` 아래 HTML 24개에서 조각 내 링크를 제외한 고유 내부 링크 목적지 1,655개를 로컬 HTTP로 요청했다. **1,655개 모두 200**, 실패 0건이었다.
- 실제 브라우저 DOM에서 증분 화면의 현재 작업별 링크와 정책 전용 과제의 비활성 상태를 읽었다. `/gt/clothing-category-gender`가 홈의 준비 전 카드로 돌아가는 것도 확인했다.
- 회귀 테스트는 링크/지원 기능, 증분 템플릿 생성 일치, 임시 fixture의 저장·상태 갱신을 확인하는 4개 테스트가 통과했다. fixture의 서버 저장 테스트는 기록된 판정의 상태 반영, 오래된 화면의 덮어쓰기 거부, 다른 검수자의 재확인을 검증했다.

## 제한

- 실제 모바일 뷰포트 확인은 하지 않았다.
- UI 저장 동작은 임시 테스트 fixture에서만 검증했다. 운영 DB, SDK 추론, 실제 사람 원장은 건드리지 않았다.
