- 기준일: 2026-09-29
- 평가자: Luna (독립 UI 평가)
- 범위: `127.0.0.1:7391`의 홈, 골든셋 검수, 증분 검수, 정책·골든셋 화면과 등록된 다섯 작업의 화면 연결
- 점수 기준: 공통 화면·탐색 25, 목적/허용값/규칙 25, 전체 정책과 SDK 전달 정책 표시 20, 링크·폼·상태 20, 읽기 쉬움·반응형 10
- 동작 제한: 읽기 전용으로 확인했다. 승인/반영/AI 실행 버튼은 누르지 않았고, SDK 호출·DB 접속·외부 시스템 쓰기는 하지 않았다.

### 증분 검수 공통 화면

네 증분 작업(`accessories-category-gender`, `bag-category-gender`, `clothing-category-gender`, `clothing-thumbnail-observation`)은 모두 같은 `incr.html` 렌더러를 사용한다. 공통 점수는 **91/100 (24 / 23 / 18 / 17 / 9)**이다. 상품 이미지·상품 링크·묶음 선택·진행률·AI 제안 버튼이 보이고, 의류 성별 증분은 URL에 과제만 지정해도 100건 화면이 표시되는 것을 확인했다. 다만 해당 과제 화면에서 상단 `정책`/`골든셋` 메뉴를 바로 누르면 현재 과제가 아니라 기본 작업인 잡화 페이지가 열린다. 펼침 메뉴에서 올바른 작업을 다시 선택할 수는 있다.

## 확인한 사실

- 로컬 서버 `/healthz`는 `200 ok`였다. `/gt-tasks`에는 GT 개선 과제 4개와 정책 페이지 5개가, `/incr-tasks`에는 증분 작업 4개가 표시됐다.
- 화면에서 홈, 잡화·가방 GT 검수, 가방 정책, 의류 썸네일 모델 성별 정책, 의류 성별 증분을 열었다. 홈과 GT 검수 화면은 좌측 공통 내비게이션, 과제 제목, 진행/업무 영역을 공유한다. 증분 화면도 `gt_review_render.py`의 공통 사이드바·스타일 상수를 가져와 같은 구조를 쓴다.
- 가방 정책 화면은 `목적 → 허용값 → 우선순위 규칙`을 앞에 보여 준다. 접어서 제공하는 두 영역에서 definitions 전체와 SDK 판독·검수·판례 에이전트에 전달되는 정책을 각각 확인할 수 있었다. SDK 투영에는 목적, 규칙명/우선순위/내용, 코드가 붙은 허용값이 표시됐다.
- 생성된 24개 HTML 화면의 내부 링크를 로컬 HTTP 요청으로 확인했다. 깨진 링크는 네 곳뿐이며 모두 두 정책/골든셋 파일의 같은 탐색 문제였다. 그 밖의 검수 카드 링크, 정책 링크, 배치 화면은 요청 시 `200`이었다.
- 데스크톱 브라우저(1280×870)에서 확인했다. 화면은 왼쪽 메뉴와 넓은 본문으로 분리되어 있고, 검수 카드는 상품 → 사진 → 판단 선택 → 근거/메모 순이다. 소스에는 좁은 화면용 CSS 구간과 동작 줄이기 설정이 있다. 실제 모바일 크기 검증은 이번 라운드에서 하지 않았다.

## 발견 사항과 수정 제안

### UI-1 — 준비 전 작업도 검수 링크를 404로 보낸다

- 재현 URL: `http://127.0.0.1:7391/f/clothing-category-gender/gt-review/policy.html` 또는 `.../gt-review/golden.html`
- 브라우저의 `골든셋 검수` 링크는 `/f/clothing-category-gender/gt-review/review.html`로 가며, 서버 응답은 `404`다. 이 작업의 홈 카드는 `준비 전`과 요청 문구를 보여 주고, 검수 진입 버튼은 내지 않는다. 따라서 준비 상태 설명은 타당하지만 정적 사이드바 링크는 그 설명과 어긋난다.
- 코드 근거: `gt_review_render.py:1385-1387`은 같은 화면 폴더에 `review.html`, `policy.html`, `golden.html`이 있다고 전제해 링크를 만든다. 검수 파일은 아직 없을 수 있다.
- 제안: 준비되지 않은 검수 메뉴는 숨기거나 `준비 전`으로 비활성 표시한다. URL 이동을 유지한다면 `/gt/<task>`로 연결해 현재 홈 카드로 돌아가게 한다.

### UI-2 — 정책 전용 작업에 없는 검수·골든셋 링크가 보인다

- 재현 URL: `http://127.0.0.1:7391/f/clothing-thumbnail-model-gender/policy-review/policy.html`
- 이 페이지의 목적·값·규칙·정책·SDK 표시 자체는 정상이다. 그러나 좌측 `골든셋 검수`는 `/policy-review/review.html`, `골든셋`은 `/policy-review/golden.html`을 열고 둘 다 `404`다. 작업 목록에는 이 작업이 정책 페이지로만 등록되어 GT 검수 화면이 제공되지 않는다.
- 코드 근거: 같은 sidebar 생성 코드가 현재 과제 폴더에 두 페이지가 항상 있다고 가정한다(`gt_review_render.py:1385-1387`).
- 제안: 정책 전용 작업은 정책 항목만 활성화하고, 제공하지 않는 기능은 링크 대신 `이 작업은 정책만 제공`처럼 직접 표시한다. 이는 페이지 누락과 의도된 미지원 기능을 구분해 준다.

### UI-3 — 증분 화면에서 정책·골든셋으로 바로 갈 때 잡화 작업이 선택된다

- 재현: `/incr?task=clothing-category-gender`에서 좌측 `정책` 또는 `골든셋` 부모 링크 확인. 실제 페이지에서 이 두 링크의 기본 주소가 잡화 정책·골든셋으로 바뀌어 있는 것을 확인했다. 펼침 목록에는 작업별 링크가 있다.
- 코드 근거: 증분 템플릿은 사이드바에 `task_id=None`을 넣고(`incr_render.py:1133`), 공통 renderer는 이때 기본 루트 링크를 사용한다(`gt_review_render.py:1367-1368, 1385-1387`). `SIDEBAR_SCRIPT`의 펼침 목록은 과제별 항목을 제공하지만, 부모 링크는 현재 `?task=` 값을 정책·골든셋의 현재 작업으로 넘기지 않는다.
- 제안: `?task=`가 있으면 그 과제의 정책·골든셋 URL을 부모 링크에 넣거나, 부모 클릭은 목록을 여는 동작으로 통일한다. 예를 들면 의류 증분 검수에서 `정책`을 누르면 의류 성별 정책으로 가야 한다.

## 재현과 근거 위치

- 로컬 경로 확인: `GET /healthz`, `/gt-tasks`, `/incr-tasks`, `/incr-data?task=clothing-category-gender&batch=20260928-142225-prod-20260928-clo-gender`.
- 링크 점검: `.claude/os/runs` 아래 생성된 HTML 24개를 읽고 내부 `<a href>`를 `127.0.0.1:7391`에 요청. 결과 4건의 404는 위 UI-1/2의 재현 경로와 일치한다.
- 공통 탐색 생성: [gt_review_render.py](../../engine/scripts/gt_review_render.py) `sidebar_html()`의 1363-1387행 및 과제 메뉴 구성.
- 증분 템플릿 공통 구조: [incr_render.py](../../engine/scripts/incr_render.py) 1129-1133행. 렌더러는 `SIDEBAR_STYLE`, `sidebar_html`, `SIDEBAR_SCRIPT`를 공통으로 사용한다.
- HTTP 화면 라우트: [serve_reports.py](../../engine/scripts/serve_reports.py) 594-616행은 증분 화면과 데이터 API를 제공한다.

## 아직 검증하지 않은 부분

- 판단 버튼, 메모, 내보내기, 증분 AI 실행은 눌러 보지 않았다. 이 동작들은 로컬 원장이나 파일을 바꿀 수 있어 읽기 전용 Round 1에서는 결과를 쓰지 않았다. 따라서 화면상 입력 컨트롤 존재와 성공 안내의 가시성은 보았지만, 저장 후 상태 회복까지 검증한 것은 아니다.
- 좁은 모바일 뷰포트에서 사진 배열과 사이드바 접힘은 확인하지 않았다.
