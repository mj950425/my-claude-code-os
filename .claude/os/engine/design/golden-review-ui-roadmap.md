# 데이터 운영 화면 — 개선점과 다음 디자인

2026-09-27 작업 대화에서 나온 개선점을 정리하고, 다음에 화면을 어떻게 바꿀지 제안한다.
수치는 적지 않는다. 건수는 화면과 `gt_review.py status`가 센다(CLAUDE.md 규칙 8).

---

## 1. 이 시스템이 하는 일 — 한 문단

**목적이 먼저 있고, 정책은 검수하면서 자란다.**

목적은 보통 정해져 있다. 예: «남성·여성 썸네일을 가려서, 고객이 남성 필터로 들어오면 퀄리티 높은 남성 이미지를
보인다». 목적은 추상적이어도 된다. 기대 효과도 계산식이 아니라 한두 문장이면 된다.
«퀄리티 높은 이미지»가 무엇인지 같은 구체적인 정의는 처음에는 없다. 그것을 만들어 가는 것이 **정책**이다.

```
목적 (추상)
  ↓  사람이 이 목적 아래에서 골든셋을 만든다 — 사진마다 칸을 채운다
골든셋
  ↓  «하네스 돌려줘» — AI 둘이 따로 보고, 골든셋과 다르게 본 칸만 올린다
골든셋 검수 화면
  ↓  사람이 고른다. AI가 가를 수 없는 경계는 «AI가 묻는 것»으로 묻는다
문답  «팔이 옷의 옆선을 일부 가리면 ‹잘림·가림›인가?» → «아니다, 통째로 보임» (근거: 골든셋 키)
  ↓  사람이 확인하면 정책에 들어간다
정책 (문답이 쌓이며 구체화된다)
  └─→ 다음 하네스 실행 때 판독 AI가 정책 전체를 읽는다 → 같은 질문을 다시 하지 않는다
```

이 고리는 성별 추론에만 쓰이지 않는다. **카탈로그에서 AI로 의미 있는 데이터를 뽑는 모든 과제**가 같은 모양으로 돈다.
속성마다 바뀌는 것은 목적, 칸, 허용값, 정책 문서뿐이고 화면과 하네스는 같다.

## 2. 이번 대화에서 이미 바꾼 것

| 영역 | 바꾼 것 |
|---|---|
| 공통 | 관리자 테마, 사이드바(홈·골든셋 검수·정책·골든셋, 마우스를 올리면 과제 목록), 기본 배율 0.75, 이름 «데이터 운영», 과제 이름 «…골든셋» |
| 골든셋 검수 | 이어 붙은 값 선택기, 답한 칸은 한 줄로, AI와 골든셋이 같은 칸은 기본값이 눌린 채로 표시(원장에는 안 적음), «AI 제안»·«지금 GT» 표시를 값 옆에, 파란색 하나로 통일, 20건씩 쪽 나누기, «반영해줘 — 고칠 목록 만들기» 버튼과 다음 쪽 버튼, 필요 없는 안내 문구 삭제 |
| AI의 질문 | 메모에서 문장을 골라내던 방식을 없앴다. AI가 칸마다 `askHuman`(경계 물음·이 사진의 자리·답별 값)으로 답하고, 화면은 그 칸 안에 «직접 봐 주세요»와 같은 호박색으로 보인다 |
| 정책 | 목적 카드(`## 목적`), 배경 카드(어디서 옮겨 왔는지, 검수에서 나온 정책과 근거 골든셋 링크), 필드 카드 안 «검수에서 정한 문답» |
| 정책 반영 | `qa` 명령 — 사람이 답한 질문을 골라, 확인을 받은 뒤 정의 문서의 `### 문답`과 `## 변경 이력`에 넣는다. 서버는 정책을 쓰지 않는다 |

## 3. 남은 개선점

### 3-1. 목적 — «과제의 첫 줄»이 되어야 한다

- **지금**: 목적은 정의 문서의 자유 서술 한 절이고 정책 페이지에만 보인다. 잡화 성별은 비어 있다.
- **바꿀 것**
  - 목적을 모양 있는 세 줄로 받는다.
    - **무엇을 가르나** — 예: 썸네일 속 사람과 상품이 어떻게 보이는지
    - **어디에 쓰나** — 예: PLP 성별 필터의 대표 썸네일 고르기
    - **기대 효과** — 추상적인 한두 문장. 계산식 아님
  - 목적은 **과제를 만들 때 가장 먼저** 받는다. 목적이 없는 과제는 하네스를 돌리기 전에 목적부터 묻는다.
  - 목적은 모든 화면의 머리에 한 줄로 따라다닌다(홈 카드, 검수 화면 제목 아래, 정책 맨 위).
    판단이 헷갈릴 때 «이 값으로 그 쓰임에 맞는가»를 떠올리게 한다.
  - 판독 AI에게는 **기준이 아닌 참고**로만 준다. 목적을 보고 값을 끌어오면 안 된다(이미 정의 문서에 적어 둠).

### 3-2. 정책 — 설명서가 아니라 «아카이브»

- **지금**: 필드 카드마다 허용값, 문답, 원문 펼치기가 있다. 처음부터 있던 규칙과 검수에서 생긴 규칙이 눈으로 구분되지 않는다.
- **바꿀 것**
  - **정책 한 줄 = 기록 한 건.** 기록마다 다음을 남긴다.
    - 무엇 — 허용값 정의, 문답, 필드끼리의 제약
    - 언제, 누가
    - 어디서 — 처음부터 옮겨 온 것인지, 검수 문답인지
    - 근거 골든셋 — 키를 누르면 그 줄로 이동
    - 상태 — 적용 중인지, 다른 기록으로 대체됐는지
  - **묶어 보기**: 기본은 필드(칸)별이다. 추가로 상품 카테고리별로 묶어 볼 수 있다.
    이를 위해 문답이 생길 때 그 상품의 표준 카테고리를 함께 남긴다. «원피스에서만 생기는 경계»가 모이면 카테고리 정책이 된다.
  - **정책 후보** 칸: 사람이 답했지만 아직 정책에 안 들어간 질문을 모아 보인다.
    같은 질문에 답이 갈렸으면 여기서 드러난다. 넣는 일은 Claude에게 «문답 정책에 넣어줘»라고 한다(서버는 정책을 쓰지 않는다).
  - **정책 밖 경우**(판정의 `:gap`)도 칸별로 쌓아 보인다. 문답도 허용값도 없는 경계라서 새 절을 열 자리다.
  - 검색: 낱말로 정책 기록을 찾는다.

### 3-3. 다음 실행에 «정책 전체가 반영됐는지»를 보인다

- **지금**: 판독 AI는 정의 문서의 필드 절 전체를 읽으니 문답도 읽는다. 하지만 화면에는 어느 정책 버전으로 읽었는지 나오지 않는다.
- **바꿀 것**
  - 배치를 준비할 때 정책 버전과 해시를 작업 목록에 남긴다.
  - 검수 화면 머리에 «정책 v◯로 판독 · 문답 ◯개 반영»을 보인다. 수는 화면이 그 자리에서 센다.
  - 정책이 바뀐 뒤 받은 판독이 옛 정책을 읽었으면 «정책이 바뀌었습니다 — 다음 거에서 새 정책으로 다시 읽습니다»라고 알린다.
  - 문답이 답한 경계를 AI가 다시 물으면 화면에 «이미 정책에 답이 있습니다»로 표시한다. AI가 정책을 안 읽었다는 신호다.

### 3-4. 홈 — 검수 대기열에서 «과제 대시보드»로

- **지금**: 과제 카드가 «답할 칸·진행률·단계»만 보인다. 검수에만 초점이 있다.
- **바꿀 것**: 과제 카드 한 장이 고리의 네 단계를 차례로 보인다 — **목적 → 골든셋 → 검수 → 정책**.
  - 목적: 한 줄
  - 골든셋: 전체 줄 수, 사람이 확인한 비율, 반영 대기
  - 검수: 답할 칸, «이어서 검수»
  - 정책: 버전, 검수에서 생긴 문답 수, 정책 후보 수
  - 맨 위 «지금 할 일»: 과제를 가로질러 급한 것만 모은다(답할 칸, 반영 대기, 정책 후보).
  - 새 과제 만들기: «목적부터 적기»로 시작한다(3-1).
  - 숫자는 모두 `/gt-tasks`(status)에 필드를 더해 받는다. 홈은 세지 않는다.

### 3-5. 골든셋 검수 화면 — 남은 것

- **AI 메모**: 이름을 «AI가 이 상품을 본 요약»으로 바꿀지 숨길지 정해야 한다. 이제 질문은 메모에 없으니 숨기는 쪽이 자연스럽다.
- **질문에 답하는 칸**: 지금은 값 버튼을 누르면 곧 답이다. 선택지(«가린다 → 잘림·가림»)를 그대로 버튼으로 만들면 한 번에 끝난다.
- **질문 고쳐 쓰기**: AI의 물음이 너무 이 상품에 붙어 있으면, 답할 때 사람이 문장을 다듬을 수 있어야 정책 문답이 깔끔해진다.
- **«정책에 넣을 만함» 표시**: 답하면서 체크해 두면 정책 후보에서 먼저 올라온다.
- **칸 이름**: «상품이 어느 쪽을 보이나» → «모델이 어느 쪽을 보나»로 바꿀지 결정이 남아 있다. 이름만 바꿀지, 정의까지 바꿀지.
- **용어**: «지금 GT», «GT 안에서 서로 모순»까지 «골든셋»으로 바꿀지 결정이 남아 있다.

### 3-6. 과제 공통 인터페이스 — 다른 속성에도 그대로

과제를 새로 붙일 때 채우는 것은 아래뿐이어야 한다. 나머지(화면, 하네스, 원장, 정책 반영)는 공통이다.

| 조각 | 자리 | 비고 |
|---|---|---|
| 목적 | 정의 문서 `## 목적` (무엇을 가르나 · 어디에 쓰나 · 기대 효과) | 3-1 |
| 칸과 허용값 | 정의 문서 `## <필드>` · `### 허용값` | 이미 있음 |
| 문답 | 정의 문서 `### 문답` | 검수에서 자란다 |
| 변경 이력 | 정의 문서 `## 변경 이력` | 근거 키가 골든셋으로 이어진다 |
| 골든셋 | `gtTask.gt` | 이미 있음 |
| AI의 질문 | `askHuman` (경계 물음 · 이 사진의 자리 · 답별 값) | 판독·반론 공통 |

## 3-7. 정책 포맷 — 확정 (2026-09-27)

결정 네 가지와 그대로 옮긴 구현이다. 모양의 정본은 [gt-task.md](../contracts/gt-task.md) «정책 문서의 모양».

| 결정 | 내용 |
|---|---|
| 규칙 모양 | 사람이 확인한 **규칙 문장 + 될 값**이 정본, AI의 물음은 `물음:` 출처 줄 |
| 옛 규칙 | 대체되면 `## 보관`으로 옮긴다 — 칸 절에는 적용 중인 규칙만(판독자가 그대로 읽는다) |
| 범위 | 표준 카테고리 경로의 아무 마디. `qa --scope`가 근거 키의 카테고리와 대조 |
| 목적 | `## 목적` 아래 세 소제목(무엇을 가르나 · 어디에 쓰나 · 기대 효과) 고정. 있으면 셋 다 있어야 로드된다 |

규칙마다 ID(`R1`, 칸 안에서 고유)·출처(검수 문답 / 직접 작성)·범위·근거 골든셋이 붙어, 정책 페이지의 «정책 기록» 한 건이 된다.

## 4. 다음 디자인 제안

캔버스 «GT 검수 화면 개편»에 개편안 아트보드를 더했다.

- **홈 — 개편안**
  - 맨 위 «지금 할 일» 띠
  - 과제 카드마다 목적 한 줄과, 네 단계(골든셋 · 검수 · 정책)의 가로 흐름
  - 카드 아래에 «새 과제 — 목적부터 적기»
- **정책 — 개편안**
  - 왼쪽에 묶어 보기(칸별·카테고리별), 가운데에 정책 기록 타임라인
  - 기록마다 출처 꼬리표(처음부터 / 검수 문답), 날짜와 사람, 근거 골든셋
  - 오른쪽에 «정책 후보»와 «정책 밖 경우»
  - 맨 위에 목적 카드(세 줄)

## 5. 정해야 할 것

1. 목적을 세 줄 모양으로 받을까? 정의 문서의 `## 목적` 아래 `### 무엇을 가르나` 같은 소제목으로 둘까?
2. 카테고리별 묶기에 쓸 카테고리 — 표준 카테고리의 어느 깊이(대·중·소)로 묶을까?
3. AI 메모 — 이름을 바꿀까, 숨길까?
4. 칸 이름 «모델이 어느 쪽을 보나» — 이름만 바꿀까, 정의까지 바꿀까?
5. 남은 «GT» 표현 — 모두 «골든셋»으로 바꿀까?
6. 가방 성별처럼 감사 사이클로 도는 과제도 홈의 같은 카드로 올릴까?
