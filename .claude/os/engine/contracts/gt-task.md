# GT 개선 과제 계약 — `gtTask`

GT를 고치는 하네스(`gt_review.py` · `gt-review.js` · `gt-blind-reader` · `gt-defender` · 스킬 `gt-improve`)는
속성을 모른다. **어떤 GT를 어떻게 읽을지는 프로필의 `gtTask` 블록과, 그것이 가리키는 정의 문서(허용값 포함)가 전부 말한다.**

새 GT를 올리는 일은 이 블록과 정의 문서를 쓰는 일이다. 코드를 고치는 일이 아니다. 예외는 하나다 — 사진이 주소(https://…)로만
있으면 내려받는 가져오기(`prerequisite`)를 속성 팩 안의 짧은 스크립트로 둔다.

모델 실행 값은 이 하네스에 없다. 검수자는 추론을 돌릴 수 없어 그 값이 어느 모델의 언제 결과인지 알 수 없고, 알 수 없는 값은
근거도 후보를 고르는 신호도 되지 못한다. 검수자가 보는 것은 GT·사진·글·정의 문서, 그리고 그것만 본 두 AI의 말이다.

## 판단을 바꾸는 자리는 정의 문서 하나다 — 프롬프트는 고정이다

과제마다 달라지는 것은 둘뿐이다 — **무엇이 답인가**(정의 문서: 허용값·값을 가르는 규칙·목적·검수에서 자란 규칙)와
**무엇을 읽는가**(프로필 `gtTask`: 필드·사진·맥락 칸·키). 판독자·반론자에게 가는 지시문(워크플로우 `gt-review.js`,
에이전트 `gt-blind-reader`·`gt-defender`)은 **일하는 방법**만 말하고 모든 과제에 하나다. 과제는 그것을 고르거나 고치지 못한다
(`gtTask.agents`를 적으면 로더가 멈춘다). 그 셋에는 과제·필드·허용값의 이름도 적지 않는다 — 테스트가 확인한다.

왜 — 과제는 계속 늘고, 판단을 고치는 사람은 프롬프트를 쓰는 사람이 아니라 데이터 운영팀이다. 기준이 프롬프트에도 있으면
과제마다 프롬프트가 갈라지고, 화면이 보여 주는 정책과 AI가 따르는 정책이 어긋난다. 판독이 틀리면 정의 문서의 그 칸 절을 고친다
(«정책에 넣어줘»·«이 칸에 ○○ 값 추가해줘»). 판독자는 매번 자기 칸 절을 통째로 읽으므로 다음 판독부터 그대로 따른다.

## 허용값은 정책이 정한다

한 필드에 들어올 수 있는 값(허용값)과 사람이 읽는 이름은 **정의 문서 하나**가 정한다 — 그 필드 절(`## <필드ID>`) 안의
`### 허용값` 아래 목록이다. 한 줄이 값 하나다.

```markdown
## color
색이 무엇인가.

### 허용값

- `RED` 빨강 — 붉은 계열이 지배적이다.
- `BLUE` 파랑 — 푸른 계열이 지배적이다.
```

- 백틱 안이 코드(원장·GT에 적히는 값), 코드 뒤부터 « — » 앞까지가 이름(화면 버튼·«다른 값…» 목록·AI 문장에 쓰는 말), 뒤는 설명이다.
  이름은 정수 필드만 빼고 필수다(참·거짓도 뜻이 필드마다 달라 필수).
- **목록 순서가 화면의 고르기 순서다.** 판독자도 같은 문서를 읽으므로, 사람이 고르는 목록과 AI가 읽는 기준이 한 곳에서 나온다.
- 프로필에 `labels`·`labelNames`를 두면 로더가 멈춘다 — 목록이 두 곳에 있으면 조용히 어긋난다.
  옛 값 대응(`legacy`)·«가를 수 없음»(`unknownLabel`)·값 여럿(`cardinality`)은 프로필에 남는다 — 값을 **어떻게 다루는가**이지 무엇이 값인가가 아니다.
- 값 목록은 정의 문서만 고친다. 단, 그 코드가 프로필의 `legacy`·`unknownLabel`·`constraints`에 쓰였으면 거기도 함께 맞춘다
  (안 맞으면 로더가 멈춘다). 값을 **뺄** 때는 그 값을 가진 GT 칸이 «허용값 밖»으로, 그 값으로 고친 판정이 «답한 뒤 정책이 바뀜»으로
  다시 올라온다 — 그 판정은 «반영해줘» 목록에서 빠지고(`outOfPolicy`) 다시 묻는다. 코드를 **바꿀** 때는 옛 코드 → 새 코드를
  `legacy`에 적으면 GT의 옛 값도, **원장에 적힌 지난 판정의 값도** 새 값으로 읽힌다 — 지난 답이 다시 올라오지 않는다(원장 파일은 그대로다).
- 제약은 값을 늘어놓지 말고 **막을 값**을 적는다(`forbid`). «무광이면 광택이 ‘강함’일 수 없다»를 `require`로 나머지 값 전부를 적으면,
  정책에 값을 하나 더할 때 그 목록이 따라가지 못해 새 값을 쓴 GT가 모두 모순으로 올라온다.
- **언제의 정책으로 그리나** — 화면은 그릴 때마다(«다음 거»·«못 읽은 거 다시 봐줘»·«GT 화면 다시 열어줘») 지금 정책의 목록을 쓴다.
  AI 판독은 배치를 준비할 때의 정책을 쓴다(판독 파일에 그 목록이 찍힌다). 정책을 고치다 틀린 줄이 생기면 화면은 배치 때 목록으로 그리고,
  다음 준비가 그 줄을 짚어 멈춘다.
- 줄 모양은 하나뿐이다 — 목록은 `### 허용값` 바로 아래 빈 줄 없는 한 덩어리, 들여쓴 줄은 앞 값 설명의 이어짐. 모양이 다른 목록 줄
  (`*` 글머리표, 백틱 없는 코드, « — » 대신 `-`·`:`), 목록이 끝난 뒤 같은 절에 다시 나오는 글머리표, 들여쓴 글머리표(목록 앞·안·뒤 어디든), 번호 목록,
  목록 바로 뒤의 들여쓰지 않은 줄, `### 허용값` 두 개나 다른 모양의 허용값 제목(«### 허용값 (…)»), 같은 `## <필드>` 절 두 개는 로더가 그 줄을
  짚어 멈춘다 — 정본을 잘못 읽으면 값이 말없이 늘거나 준다. 설명 글머리표는 다른 `###` 절에 둔다.
- 감사 사이클의 정책 `policy.md`는 속성 하나에 문서 한 장이라 최상위 `## 허용값`을 쓰고 이름이 없다(정책 인덱스가 프로필
  `labels`와 대조해 `LABEL_NOT_IN_PROFILE`을 낸다 — [policy-layer.md](policy-layer.md)). GT 개선 과제는 한 문서에 필드가 여럿이라 필드 절
  아래 `### 허용값`이고, 화면 버튼에 쓰므로 이름이 필수이며, 프로필에는 목록이 없다(대조할 둘째 목록을 두지 않는다).


아래 예시는 일부러 가짜 속성(상품 색상·광택)으로 쓴다. 엔진 문서가 실제 과제의 어휘를 알기 시작하면
그 과제에 맞춰 문서가 휜다.

## 왜 (키, 필드)가 단위인가

감사 사이클은 「상품 하나에 라벨 하나」를 전제한다. 그런데 이미지 메타데이터 GT는 한 장에 칸이 여럿이고,
색상·소재 GT는 상품 하나에 칸 여럿이 붙는다. 단위를 **(키, 필드) 한 칸**으로 내리면 모두 한 모양이 된다 —
라벨 하나짜리 GT는 필드가 하나인 과제, 메타데이터 GT는 필드가 여럿인 과제다.

다만 **증거는 키 단위로 한 번만 읽힌다.** 같은 사진을 필드마다 따로 읽히면 같은 눈이 여러 번
서로 다른 전제에서 출발한다. 그래서 판독의 단위는 키(건), 판정의 단위는 칸이다.

## 블록

```jsonc
"gtTask": {
  "schemaVersion": "gt-task-v1",
  "unit": "상품",                      // 자유 문자열. 화면 머리말(«상품 단위»)에만 쓴다
  "keyField": "sku" | ["itemNo", "imageNo"], // 열 하나 또는 복합 키. 비었거나 겹치면 멈춘다.
                                      // 복합 키는 keyField 순서대로 조각을 «|»로 이은 문자열이다(어댑터의 key, --key, 원장 모두 같다)
  "groupField": "maker",              // (선택) 화면에 함께 적을 묶음
  "titleField": "itemTitle",          // (선택) 화면 제목. 판독자에게 줄 맥락·글로 쓰려면 "titleAsEvidence": true
  "linkField": "pdpUrl",              // (선택) 상품 페이지 주소 칸. GT 행에 없으면 사진 원본 행(같은 키)에서 찾는다. 골든셋 표의 키가 이 주소로 열린다
                                      // (한 줄을 거의 가리키는 열이라 기본은 막는다. 키 열은 늘 막는다. 묶음 열은 막지 않는다)
  "definitions": "<경로>.md",          // 필드마다 `## <필드ID>` 절. 판독자·반론자가 읽는 유일한 기준. 절이 없으면 멈춘다.
                                      // 다른 문서에서 옮겨 왔으면 머리(front matter)에 seededFrom(원문 경로 목록 — `.claude/`로
                                      // 시작하면 이 저장소, 아니면 source.repository 기준)과 seededFromSha256(원문마다 해시, 같은 순서)을
                                      // 적는다. 원문이 바뀌면 prepare가 warnings.definitionsSeedChanged로, 이 컴퓨터에서 찾지 못하면 warnings.definitionsSeedMissing으로 알리고 막지는 않는다.
                                      // 해시를 적지 않으면 확인하지 않는다 — 옮겨 왔다면 적는다
  "definitionsRoot": "project",       // (선택) definitions 경로의 기준
  "gt": {
    "path": "...", "root": "project" | "source" | "output",  // runs/ 아래는 거절한다 — 정답의 원본이 될 수 없다
    "sourceField": "source",          // 줄의 출처
    "fieldSourcesField": "fieldSources", // 칸별 출처(키는 필드 id — gtField가 아니다). 필드가 여럿이면 필수. 필드가 하나면 없어도 되고, 그때는 줄 출처(sourceField)를 고친다.
                                         // 선언만 하면 되고 GT에 그 열이 아직 없어도 된다 — 없는 줄은 줄 출처 등급을 따르고, «반영해줘»가 열을 만든다(newColumns)
    "upstream": {"kind": "sheet", "note": "사람이 읽는 원본 설명", "refresh": "개발자가 돌리는 새로 고침",
                 "acceptsEmpty": false, "mirrorFields": ["finalLabel"], "locatorFields": ["sheet", "row", "cell"],
                 "rowCheck": {"row": "row", "cell": "cell", "sheet": "sheet", "rowSheet": "첫 탭"},
                 "columns": {"color": "최종 색"},
                 "headerNames": {"sku": "품번", "sheet": "탭", "reviewer": "검수자", "reason": "메모"}},
                                      // rowCheck(선택): 위치 열 중 행 번호 열과 A1 주소 열. 주소의 숫자가 행 번호와 다르면 그 줄은 위치를 비우고
                                      // «위치 불일치 — 키로 찾으세요»로 적는다(export의 locatorConflicts). 한쪽을 믿으면 다른 상품의 줄을 고친다.
                                      // 행 번호가 한 탭의 번호뿐이면 sheet(탭 열)·rowSheet(그 탭 이름)를 함께 적는다 — 다른 탭 줄은 행 번호만 비운다
                                      // headerNames(선택): 붙여 넣을 목록의 키·위치 열, 그리고 판정한 사람(reviewer)·이유(reason) 열의
                                      // 머리글을 상류 시트의 말로. 상류 새로 고침이 사람·근거 칸도 읽으면 그 칸 이름을 적는다
                                      // (선택) 이 파일이 더 위의 원본(검수 시트·계보 합치기)에서 다시 만들어지면. 선언하면
                                      // apply는 거절하고 export가 상류에 붙여 넣을 목록(upstream-patch.csv — 위치 열·상류 열 이름 포함)을 낸다.
                                      // mirrorFields는 같은 값을 비추는 열 — 고치면 함께 고친다. **필드가 하나인 과제에서만**(여럿이면 한 필드의 답이
                                      // 다른 필드의 거울을 덮는다 — 로더가 멈춘다). acceptsEmpty가 아니면 «비워야 한다»(CLEAR)를 받지 않는다.
                                      // upstream-patch.csv는 BOM 붙은 UTF-8이고 머리글이 사람 말이다(키·위치 열 · 고칠 열 · 지금 값 · 새 값 · 새 값 이름 · 판정한 사람 · 이유)
    "supersededBy": {"glob": "*.lineage.json", "baseField": "derivedFrom", "markerSuffix": ".lineage.json", "newerSuffix": ".jsonl"}
                                      // (선택) 새 판이 옛 판을 어떻게 밝히는가. 같은 폴더에서 glob에 맞는 표지 파일 가운데 baseField가 이 GT를
                                      // 가리키는 것이 있으면 멈춘다. 새 판의 이름은 표지 이름에서 markerSuffix(기본: 표지의 확장자)를 떼고
                                      // newerSuffix(기본 .jsonl)를 붙인 것 — 멈춤 문장이 그 파일을 가리킨다
  },
  "authority": {                      // 출처 → 등급. 정규식. 맞는 것이 없으면 UNKNOWN — 모름 등급은 실행 값이 없으면 후보로
                                      // 올라오지 않는다(참고 등급만 GT_REFERENCE_ONLY). 패턴 오타는 warnings.sourcesUnclassified가 센다
    "trusted": ["^HUMAN_"],           // 사람이 확정 — 뒤집으려면 기준이 높다
    "reference": ["^AUTO_", "GUESS"],  // 사람 확인 전
    "default": "reference"            // (선택) 출처가 없거나 어느 패턴에도 안 맞는 칸의 등급(trusted·reference·unknown, 기본 unknown).
                                      // 출처 열이 없는 손 라벨 GT는 reference로 두어야 채워진 칸을 GT를 모르는 눈이 다시 본다
  },
  "correctionSourcePrefix": "OPS_REVIEW",  // (선택) 내보낸 정정의 출처 이름 앞머리. 없으면 GT_REVIEW_<과제ID>. 이 앞머리로 시작하는
                                      // 출처(이 하네스가 쓴 사람 판정)는 authority 선언과 무관하게 사람 확정 등급이다
  "fields": [{
    "id": "color",
    "name": "대표 색",                  // 운영팀이 읽는 이름
    "gtField": "mainColor",           // (선택) GT 열 이름이 id와 다를 때. 평평한 열만(점 경로는 거절한다)
    "valueType": "string" | "boolean" | "integer", // (선택) 원본 값의 형. 라벨은 늘 문자열("true"·"2")로 쓰고(아니면 멈춘다), 내보낼 때 형을 되돌린다
    "alternativesField": "colorAlternatives", // (선택, 값 하나 필드만) 같이 맞다고 적어 둔 값의 열. 실행이 그 값을 내면 어긋남이 아니다.
                                      // 고칠 때 새 값이 그 목록에 있으면 뺀다
    // 허용값·이름표는 여기 적지 않는다 — 정책(정의 문서)이 정본이다. 위 «허용값은 정책이 정한다» 절. name은 필수
    "cardinality": "one" | "many",    // many면 값 여럿(집합). 안에서는 정렬해 `|`로 잇는다
    "legacy": {"CRIMSON": "RED"},     // 옛 값 → 지금 값. 비교 전에 옮긴다
    "fillMissing": true,              // GT가 빈 칸을 채울 후보로 올릴 것인가
    "unknownLabel": "UNSURE"          // (선택) «가를 수 없음»을 뜻하는 라벨. 화면이 그 값으로 고치는 버튼을 따로 둔다
  }],
  "constraints": [{                   // (선택) GT 한 줄 안의 모순
    "id": "MATTE_HAS_NO_SHEEN", "text": "사람이 읽는 문장",
    "when": {"finish": "MATTE"},
    "require": {"sheen": ["NONE", "LOW"]} // 이 값들 중 하나여야 한다. 나머지 전부를 늘어놓게 되면 forbid를 쓴다
    // "forbid": {"sheen": ["HIGH"]}   // 이 값이면 안 된다. require와 forbid 중 하나는 있어야 한다
  }],
  "images": {                         // (선택) 판독자와 사람이 볼 사진
```

## 다루는 값과 다루지 않는 값

- **열거형만 다룬다.** 필드마다 허용값 목록이 있다(둘 이상). 수치(혼용률 30%)나 자유 글은 이 하네스의 범위 밖이다.
- **긴 모양(한 줄에 {키, 필드, 값})의 GT는 받지 않는다.** 한 줄이 한 단위(키)여야 한다 — 긴 모양은 그 파일을 가진 쪽이
  넓혀서 둔다. 이 저장소에 바꾸는 단계는 없다.
- **GT 파일은 평평한 JSONL이고, 그 파일을 가진 쪽(외부 레포)이 JSONL로 둔다.** 이 저장소에는 시트·CSV를 GT로 바꾸는 단계가 없다 —
  `prerequisite`는 `runs/` 아래 **파생 입력**(사진 색인)을 만드는 자리이고, `runs/` 아래 GT는 로더가 거절한다(지워도 되는
  자리가 정답의 원본일 수 없다). 원본이 시트면 시트를 가진 쪽의 새로 고침이 JSONL을 만들고, 그 사실을 `upstream`으로 밝힌다.
- **후보는 GT에 줄이 있는 키에서만 나온다.** 사진 색인에는 있지만 GT 줄이 없는 장(아직 라벨이 없는 사진)은 올라오지 않는다 —
  그런 장을 올리려면 먼저 GT에 빈 줄을 만든다(그러면 `fillMissing`이 채울 칸으로 올린다).
- 값 여럿 필드(`many`)는 **순서 없는 집합**만 다룬다(순서가 뜻인 열은 범위 밖 — «유지»도 정렬한 순서로 다시 쓴다). 글자로 적힌
  값 여럿은 `|`로만 나눈다(쉼표·세미콜론 구분은 그 파일을 가진 쪽이 `|`나 목록으로 둔다). 내보낼 때는 원본 칸의 모양대로 —
  목록이던 칸은 목록, «A|B» 글자이던 칸은 글자로 되돌린다.
- 값 여럿 필드(`many`)는 **정렬한 집합**으로 비교한다. 제약의 `when`·`require`도 그 집합 전체(정렬해 `|`로 이은 값)와
  **정확히 같을 때**만 걸린다 — 부분집합으로 보지 않는다. 제약의 값은 로더가 필드 규칙으로 옮기고 허용값인지 검사한다
  (오타·형이 다른 값이면 멈춘다). `when`의 값 여럿 필드는 목록으로 적어도 된다.
- 참·거짓·정수 원본 값은 `valueType`을 선언해야 받는다. 선언 없이 오면 멈춘다 — 조용히 문자열로 바꾸면 내보낼 때 형이 바뀐다.
- 중첩 열(`meta.sheen`)은 읽지 않는다. 평평한 열만.
- **모든 칸이 사람 확정(trusted)인 GT에서는 후보가 나오지 않는다** — 참고 등급 신호는 확정 칸을 보지 않는다(prepare가 «이 설정으로는
  걸리는 칸이 하나도 없습니다»로 말한다). 그런 GT를 GT를 모르는 눈으로 다시 보려면 출처 등급을 `reference`로 둔다(`authority.default`).
  확정 칸의 표본 검사는 아직 없다.
- 제약은 **선언된 필드끼리만** 건다. 범주·맥락 열에 따라 허용값이 달라지는 규칙(«이 범주에서는 이 값이 불가능»)은 다루지 않는다 —
  필드 제약으로 표현하거나 GT를 가진 쪽이 검사한다.

## 신호와 순서

| 신호 | 뜻 | 먼저 보는 이유 |
|---|---|---|
| `GT_SELF_CONTRADICTION` | 선언된 제약을 GT 한 줄이 어긴다 | 둘 중 하나는 반드시 틀렸다 |
| `GT_OUT_OF_RANGE` | GT 값이 허용값 밖이다 | 대응 없는 옛 값이거나 오타다 |
| `GT_CHANGED_SINCE_DECISION` | 사람이 답한 뒤 원본이 «본 값»도 «고른 값»도 아니게 바뀌었다 | 사람이 본 값이 아니다 |
| `POLICY_CHANGED_SINCE_DECISION` | 사람이 고른 값(유지면 본 값)이 지금 정책의 허용값에 없다 — 정책에서 그 값을 뺐다 | 그 답은 지금 정책으로는 답이 아니다. «반영해줘» 목록에서도 빠진다(`outOfPolicy`) |
| `GT_MISSING` | `fillMissing` 필드가 비었다 | 채울 칸 |
| `GT_REFERENCE_ONLY` | 참고 등급 라벨이다 | 사람이 확인한 적이 없다 — GT를 모르는 눈이 한 번 본다. 같은 값을 내면 `agreed.jsonl`이 다음 순서를 뒤로 민다 |
| `BLIND_DISAGREES` | (판독 뒤에만) 고른 건의 **후보가 아닌** 칸에서 GT를 모르는 판독이 확신 있게(HIGH) 허용값 안의 다른 값을 냈다. 반론도 그 칸에 불린다 | 실행과 GT가 함께 틀린 칸은 비교할 것이 없어 조용하다 — 판독자는 어차피 필드를 전부 읽으므로 그 판독을 버리지 않는다. 빈 칸과 사람이 이미 답한 칸은 보지 않는다 |

같은 신호 안에서는 **참고 등급 → 모름 → 사람 확정** 순서다. 사람 확정을 뒤집는 일이 가장 기준이 높다.
참고 등급 라벨이라도 실행이 독립적으로 같은 값을 냈으면 올리지 않는다 — 이미 한 번 확인된 것이다.
지난 판독에서 GT를 모르는 AI가 **지금과 같은 GT 값**을 확신 있게 낸 칸은 **끝난 것으로 본다** — `사람 확인 전 라벨`(`GT_REFERENCE_ONLY`)
하나로만 뽑힌 칸이면 다시 올리지 않는다(`agreed.jsonl` — 원장이 아니다. 사람의 판정이 아니므로 원장에는 적지 않고, GT 출처 등급도 그대로다).
다시 올라오는 때는 둘이다 — GT가 바뀌었거나(그때의 값과 달라져 동의가 맞지 않는다), 그 칸의 정의 절이 바뀌었을 때(동의마다 그 절의 지문
`policy`를 적는다). 모순·허용값 밖처럼 다른 신호가 함께 있는 칸은 동의가 있어도 올린다. 사람이 **보류**한 칸만 남은 건은 새 후보 뒤로 민다.
왜 — 전에는 동의한 칸을 뒤로 미루기만 해서, 새 후보가 떨어지면 사람이 이미 보고 넘어간 칸(누를 것이 없다고 안내한 칸)이 통째로 다시 올라왔다.
제약은 **사람이 고친 값을 얹은 줄**로 따진다. 모순이 남은 칸(`GT_SELF_CONTRADICTION`)과 정책이 바뀐 칸(`POLICY_CHANGED_SINCE_DECISION`)은
지난 배치에서 «유지»로 답했어도 다시 올라오고, **그 배치에서 준 답만** 답으로 센다(`reasked`).
증거(사진·글)가 하나도 없는 건도 화면에는 싣고(`NO_EVIDENCE`) 판독자만 띄우지 않는다 — 모순·범위 밖은 판독 없이도 사람이 가른다.

## 배치와 눈가림

- `prepare`는 부를 때마다 `batchId`를 새로 만들고 지난 배치의 화면·판독 결과·사진을 지운다.
  워크플로우가 돌려준 `batchId`가 다르면 `finish`가 거절한다.
- 판독자는 **자기 건의 판독 파일 하나**(`gt-review/reader/<무작위 이름>.json`)만 받는다. 키·GT·실행 값·출처·건 이름이
  없다. 필드는 과제가 선언한 순서로 **전부** 준다(후보 칸만 주면 어느 칸이 다투는지가 목록 모양으로 샌다). 사진도 판독자 몫을
  따로 복사해 무작위 이름 폴더(`P01`)에 둔다. 사람 화면의 사진은 `images/`에 따로 있다.
- `gt-review/workflow-args.json`은 무엇을 돌렸는지 되짚는 기록이다 — 건 이름·필드·허용값·사진 수만 담고 **GT 값도 판독 파일
  이름도 담지 않는다**(둘은 표준 출력의 workflowArgs에만 붙는다 — 테스트가 확인한다).
- 판독 파일 이름과 건의 대응, 그리고 GT 값은 판독 파일·워크플로우 기록 어디에도 쓰지 않는다. 워크플로우 인자(표준 출력)와
  그 반환값에만 있다.
- **눈가림이 어디까지 구조이고 어디부터 약속인가.** 판독자가 자기 입력에서 답에 닿을 **실마리**(이름·경로·순서·열)는 구조로
  없앴다. 그러나 저장소 안에는 사람 화면용 작업 목록(`worklist.json`)과 GT 원본 자체가 있고, 판독자의 Grep·Glob은 거기 닿을 수
  있다(한 건짜리 배치면 대응도 뻔하다). 그 선은 역할 파일과 프롬프트의 금지, 읽기 전용 도구, 그리고 뒤따르는 반론·사람 판정으로
  지킨다 — «저장소 안에 실마리가 전혀 없다»는 주장은 하지 않는다.
- 사람 앞에 놓였지만 답 없이 넘어간 칸(«다음 거» → «네»)은 `shown.jsonl`에 적어 다음 화면에서 뒤로 민다(순서 힌트 — 원장이 아니다).
- 사람 화면은 칸마다 정의 문서의 그 필드 절을 접어 싣는다(«이 칸의 기준 보기») — 사람도 판독자와 같은 기준을 본다.
- `prepare`는 `agreed.jsonl`·`shown.jsonl`·`blind.jsonl`(화면에 올라갔던 «증거만 본 AI와 다름» 칸 — 같은 GT 값이면 보류·넘김 뒤에도
  다시 후보로 올린다)·`export/` 말고 `gt-review/` 아래를 전부 지운다(남길 것 목록 — 코드의 `KEEP_ACROSS_BATCHES`,
  테스트가 이 목록과 계약을 맞춘다).
  옛 판의 파일이 이름이 달라 살아남지 않게. `export/`는 사람에게 «붙여 넣어 주세요»라고 건넨 목록이라 남긴다
  (키와 GT가 다 들어 있으므로 판독자가 열지 않는 자리다).
  `golden-thumbs/`는 골든셋 화면(`golden.html`)이 키마다 대표 사진을 작게 줄여 둔 폴더라 배치와 무관해 남긴다(다시 줄이지 않게).
  파일 이름은 키의 해시다 — 판독자에게 주지 않는 자리다.
- `prepare --reread`는 새 배치를 만들지 않고 지금 화면의 «못 읽은» 건만 다시 판독하게 한다. `finish`는 같은 배치의 결과를 합친다.
- 에이전트 유형이 세션에 없으면 워크플로우는 다른 에이전트로 대신 세우지 않고 멈춘다(`needsRestart`).
  기본 에이전트는 쓰기 도구를 가져 «읽기만 한다»가 지시로만 남기 때문이다.

## 정책 문서의 모양

정의 문서(`gtTask.definitions`) 하나가 이 과제의 정책이다. 판독자·반론자는 칸 절을 통째로 읽고, 화면은 같은 문서를 그린다.
로더는 아래 모양을 허용값처럼 엄격하게 읽는다 — 모양이 다른 줄, 없는 값 코드, 같은 ID가 둘이면 멈춘다.

```markdown
---
id / version / owner / updatedAt / seededFrom(+Sha256)     ← 규칙을 넣으면 version이 하나 오른다
---
# <과제> 정책
서문 — 어디서 옮겨 왔는가(정책 페이지의 «배경»)

## 목적                       ← 있으면 세 소제목이 모두 있어야 한다. 판독 기준이 아니다
### 무엇을 가르나
### 어디에 쓰나
### 기대 효과

## <필드ID>                   ← 칸마다 하나
정의 문단
### 허용값
- `CODE` 이름 — 설명
### 규칙                      ← 적용 중인 규칙만. 검수에서 자란다
- `R1` <규칙 문장> → `CODE`    (→ 뒤는 없어도 된다)
  - 물음: <이 규칙을 낳은 AI의 물음>
  - 출처: 검수 문답 · 날짜 · 사람 · 판정 ID   |   직접 작성 · 날짜 · 사람      ← 반드시
  - 범위: <상품 카테고리 이름 한 마디>(쉼표로 여럿, 없으면 모든 상품)
  - 근거: <골든셋 키>(쉼표로 여럿)

## 필드끼리의 제약
## 보관                       ← 대체된 규칙. 판독자는 읽지 않아도 된다(칸 절에 없다)
- `<필드ID>/R0` <옛 문장> → `CODE`
  - 출처: …
  - 대체: R1 · 날짜 · 사람
## 변경 이력                  ← 한 줄 = 정책 변경 하나. «근거:» 키는 골든셋 화면의 그 줄로 이어진다
- 날짜 · v6 · <칸 이름> R1 추가, R0 대체(사람) — 근거: 키1, 키2
```

- **규칙 문장이 정본이고 물음은 출처다.** «물음 → 답»은 이번 상품에 붙은 말이라 다음 판독자에게 경계가 흐리다.
- **ID는 칸 안에서 고유하다**(보관 포함). 코드에 적지 않는다 — 규칙은 문서에서 스스로 걸린다.
- **범위**는 상품 카테고리 경로의 어느 마디든 된다. `qa --scope`는 근거 키의 카테고리에 그 마디가 있는지 지금 화면으로 대조한다.

## 원장은 하나

- 판정 원장은 `.claude/gt/<프로필ID>/gt-review/decisions.json`이다. `runs/`에 두지 않는다 —
  `runs/`는 지워도 되지만 사람의 답은 아니다. 판정은 다섯이다 — `CORRECT`(값으로 고침) · `CONFIRM`(지금 값이 맞다) ·
  `LEAVE_EMPTY`(빈칸이 맞다, 빈 칸에만) · `CLEAR`(값이 있지만 비워야 한다) · `HOLD`(보류, 다음에 다시 나온다).
- 제약을 어기게 되는 판정은 막지 않고 `constraintWarnings`로 그 자리에서 알린다 — 두 칸을 한 번에 고칠 수 없어서다.
- 판정마다 `basis`는 `definitions#<필드ID>`다. 이 과제의 경계는 판례가 아니라 정의 문서의 그 절이다. 사람이 «기준에 없는 경우»에
  표시하면 `definitions#<필드ID>:gap`이 되고, `status`·`export`가 필드마다 센다 — 정의에 절을 더할 자리다.
- AI가 사람에게 묻는 말은 칸마다 표준 모양 하나(`askHuman` — `question`·`here`·`imageIds`·`options`)로만 받는다. `question`은
  사진 번호도 이 상품 이야기도 없는 **경계 물음**이고, `options`는 답마다 될 허용값이다(허용값 밖의 선택지는 화면이 버린다).
  물음이 있으면 확신은 `LOW`다. 화면은 그 물음을 그 칸에 보이고, 사람이 누른 판정은 `basedOn.ask`에 물음을 함께 남긴다.
  메모(`note`)에서 물음 문장을 골라내는 일은 표준 물음이 없던 옛 배치에만 한다.
- **사람이 답한 물음은 곧 정책이다(검수 문답).** 따로 옮기는 단계가 없다 — `answered_questions`가 원장에서 읽어
  정책 페이지(`/gt-qa`, 칸 카드의 «검수 문답»)와 다음 `prepare`의 판독자 인자(`common.answered`, 그 상품 자신의 답은 `skipQa`로 뺀다)로 보낸다.
  판정이 어느 물음의 답인지는 판정에 남은 `basedOn.ask`, 없으면 화면이 그 칸에 보인 물음의 기록(`asked.jsonl`, CLI render가 덧붙이기만 한다)에서 읽는다.
- 여러 문답을 한 문장으로 다듬고 싶을 때만 `qa`로 **규칙**을 만든다(선택) — 아래 «정책 문서의 모양». 사람이 고른 판정(`--add`), 사람이 확인한
  규칙 문장(`--rule`), `--yes`가 모두 있을 때만 넣는다. 서버는 이 일을 하지 않는다(서버가 쓰는 것은 원장뿐이다).
  한 번에 한 칸의 규칙 하나 — 답이 갈린 판정은 한 규칙으로 묶지 않는다.
- 판정은 그 판정을 한 **배치**(`batchId`)를 남긴다. 보류는 그 배치의 화면에서만 답이다 — 다음 배치에서는 다시 묻는다.
- 말로 받은 판정(`record`)도 사람이 본 GT 값(`--expect`, 빈칸이면 `--expect-empty`)이 없으면 받지 않는다.
- 판독자·반론자는 모든 과제에 공통이다(`gt-blind-reader`·`gt-defender`). 과제는 바꾸지 못하고(`agents`를 적으면 로더가 멈춘다), 로더는 둘이 읽기 도구만 가졌는지 확인한다.
- 모든 판정은 **사람이 본 GT 값**(`expectedBefore`)을 함께 보낸다. 다르면 기록기가 거절한다.
- 모든 판정은 **들어온 길**(`channel`)을 남긴다 — `screen`(칸 버튼) · `screen-bulk`(건의 «이 값들을 GT로 유지») ·
  `spoken`(Claude가 말을 받아 적음). 기록기가 기본값 없이 요구한다. 나중에 원장만 보고 말로 받은 판정을 가려 되짚을 수 있게.
- **감사 사이클의 원장(`gt` 블록)을 쓰는 프로필에는 `gtTask`를 선언할 수 없고**, 한 GT 파일을 두 프로필이
  가리킬 수도 없다(`prepare`가 멈춘다). 한 GT에 판정 원장이 둘이면 화면마다 다른 답을 그린다.
  그런 GT로 온 요청은 `tasks`의 `otherDoors`가 가리키는 문으로 보낸다.
- 상류가 있는 과제는 건넨 줄을 `.claude/gt/<id>/gt-review/handed-out.jsonl`에 덧붙인다(목록 번호와 함께). 이것은 파생물이 아니라
  **상태**다 — 무엇을 건넸는지는 원장에서 다시 만들 수 없으므로 지우지 않는다. 목록의 «새로»는 가장 최근 목록 번호에 처음 건넨 줄이고
  (새 판정 없이 다시 내면 같은 줄), «되돌림»은 건넨 정정을 그 뒤 **정정 전 값에 대해** 유지·빈칸 유지·보류로 거둔 칸이다(새 정정이 그 칸을 대신하거나, 건넨 새 값에
  «맞다»고 했거나, 상류가 다른 값으로 옮겨 간 뒤의 답이면 되돌림이 아니다). 되돌림은 거둔 정정마다 한 번 건넨다 — 보류를 다시 눌러도
  «새로»가 아니다. 기록은 «반영해줘»(`export`)가 남기고, `apply`의 미리 보기는 아무 파일도 쓰지 않는다(건넨 기록도, 보여 준 목록의 표지 `export.json`도 — 표지가 옮겨지면 `apply --yes`가 사람이 보지 않은 판정까지 넣는다). 되돌릴 값은 건넬 때의 상류 칸 값(거울 열)이고 비어 있었으면 «칸을 비워 주세요»다. 상류가 거둔 값을 이미 품었으면(거울 열 =
  건넨 새 값) 되돌릴 때까지 늘 싣고, 아니면 처음 실은 목록에만 싣는다. 되돌림이 있으면 목록은 늘 건넨다.
- `export`는 원본을 고치지 않는다 — 정정·확인 목록(`.claude/gt/<id>/gt-review/`, 원장의 파생물)과 고친 GT 사본
  (`runs/<id>/gt-review/export/gt.corrected.jsonl`, 지워도 되는 파생물 — **정답이 아니다**)을 만든다. 정정 줄은 복합 키를
  `keyFields`로 풀어 함께 적는다(원래 형 그대로). 정정 줄에는 필드 ID(`field`)와 GT 열 이름(`column`)이 함께 있고,
  원본에 이미 들어간 정정도 `applied: true`로 남는다. 옛 이름으로 적힌 값을 «맞다»고 확인하면 지금 이름으로 다시 쓴다.
- 원본이 이 레포 안(`.claude/gt/<id>/gt.jsonl` 같은)이면 GT는 GitHub에서 관리한다 — 넣은 뒤 `publish --yes`가 **고친 GT와 판정 원장 폴더만**
  담은 커밋을 새 브랜치 `gt/<과제>-<시각>`로 밀고 PR을 연다. 작업 트리·지금 브랜치는 건드리지 않는다(임시 인덱스). 원본에 아직 넣지 않은
  정정이 있으면 멈춘다 — PR의 GT와 원장이 다른 말을 하지 않게. 원본이 레포 밖이면 원장만 올라간다. 되돌리기용 사본(`.before-gt-review-*`)은
  올리지 않는다(`.gitignore`) — 이력은 git이 갖는다.
- 원본에 넣는 일은 `apply --yes`이고, 사람이 «반영하기»를 누르거나 «반영해줘»(«넣어줘»)라고 말하면 `export` 바로 뒤에 묻지 않고 부른다 —
  누르거나 말한 것이 곧 확인이다(목록을 보여 주고 한 번 더 묻던 단계는 사람을 멈춰 세우기만 했다. 팀 GT로 가는 PR에서 바뀐 줄을 다시 본다).
  **방금 만든 목록 그대로**만 넣는다 — 마지막 `export`가 적은 원본 해시·마지막 판정 번호가 지금과 다르면 거절한다. 바뀌지 않은 줄은 글자 그대로 두고 바뀐 줄만
  다시 쓰며, 원본 옆에 사본을 남긴다. `upstream`이 선언된 GT에는 넣지 않는다.
- 판정 뒤 원본 GT가 바뀌었으면 그 칸의 판정은 내보내지 않고 `stale`로 보고한다.

## 이 문으로 고치지 않는 GT — 감사 사이클의 GT

판례를 쌓는 속성처럼 **감사 사이클**(정책·판례·심판·계보 합치기)을 가진 GT는 이 하네스로 고치지 않는다. `tasks`가
`otherDoors`로 그 GT와 그 문(감사의 GT 정정 화면)을 알려 주고, 스킬은 요청을 그쪽으로 보낸다.

- **왜** — 그 GT의 판정은 «어느 판례 위의 판단인가»를 함께 남기고, 판례가 열려 있으면 GT로 나가지 않고 기다린다
  (CLAUDE.md 규칙 5). 이 하네스의 경계는 정의 문서의 필드 절 하나뿐이라, 같은 GT를 여기서 고치면 판례를 건너뛴
  판정이 생긴다. 그리고 그 GT는 계보 원본 여럿을 순위로 합친 결과라, 한 파일만 고치면 다음 합치기에서 사라진다.
- **막는 방법** — 한 프로필에 `gt`와 `gtTask`를 함께 둘 수 없고, 과제의 GT가 사이클의 합친 GT나 **계보 원본 파일**
  (`gt.sourceDir` 아래 `lineages[].pattern`·`corrections.pattern`)과 겹치면 `prepare`가 멈춘다.
- **합칠 계획** — 사이클 원장을 `.claude/gt/<id>/`로 옮기고(규칙 5가 이미 이유를 적었다), `gtTask`의 판정에 판례를 고를 자리를
  붙이면 두 문이 한 원장을 쓸 수 있다. 그때까지는 문이 둘이되 원장은 GT마다 하나다.

## 새 GT를 올리는 순서

1. 속성 팩 폴더(`attributes/<id>/`)에 `profile.json`과 `definitions.md`를 쓴다. 정의 문서에는 필드마다 `## <필드ID>` 절과 그 안의
   `### 허용값` 목록을 둔다(위 절의 줄 모양). 프로필 맨 위에는 `schemaVersion`
   (`catalog-data-profile-v1`)·`id`·`displayName`·`attributeName`·`subjectName`·`outputRoot`가 있어야 한다 — 하나라도 없으면
   `tasks`의 `brokenProfiles`에 까닭과 함께 나온다(과제 목록에서 조용히 빠지지 않는다).
2. `python3 .claude/os/engine/scripts/gt_review.py prepare --task <id> --limit 1`로 한 건이 준비되는지 본다.
   «돌았다»로 끝내지 않고 `worklist.json`의 `warnings`를 본다 — 조용한 설정 실수는 여기서만 보인다:
   `evidenceColumnsNeverSeen`(맥락·글 열 이름 오타),
   `counts.noEvidence`(사진·글 연결), `imagesMissing`(못 연 사진 — 경로·주소), `sourcesUnclassified`(등급 패턴에 안 맞는 출처). 로더가 멈추는 실수(선언 안 된 필드, 허용값 밖 옛 이름·이름표, 한 필드 안에서 겹치는 이름표, 답·키 열을 맥락으로,
   두 필드가 한 GT 열을 가리킴, 답 열이 키·출처·칸별 출처·대체 정답·상류 거울·위치 열과 같음)는
   문장으로 멈춘다.
3. 운영팀에게는 «<displayName> GT 개선해줘»라고 요청하면 된다고만 알린다.
