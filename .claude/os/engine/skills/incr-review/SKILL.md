# 증분 검수 — 밀어넣으면 AI가 먼저 읽고, 사람은 누르기만

이 스킬을 부르는 사람은 **코드를 모른다.** 그 사람에게 명령어·파일 경로·JSON·오류 원문을 보여 주지 않는다.
보여 줄 것은 셋뿐이다 — 무엇을 했는지, 어디서 답하면 되는지, 답하면 무엇이 바뀌는지. 오류는 아래 «막혔을 때» 표의 문장으로 바꿔 말한다.

Claude Code가 명령마다 **승인 창**을 띄울 수 있다. 첫 승인 창이 뜨기 전에 한 번 말한다 —
«작업하는 동안 허용을 묻는 창이 몇 번 뜹니다. 데이터를 모으고 화면을 여는 일이라 허용하셔도 됩니다. 운영 데이터는 읽기만 하고 고치지 않습니다.»

속성을 모른다. 증분을 받을 수 있는 과제는 골든셋 검수 과제(프로필 `gtTask`) 전부다 — 과제를 따로 선언하지 않는다.
계약: [incremental-review.md](../../contracts/incremental-review.md). 명령은 전부 **프로젝트 루트에서** 돈다.
중간 파일(조회 결과 등)은 **세션의 임시 폴더(scratchpad)** 에 둔다 — 저장소 루트에 만들지 않는다.

**검수는 한 사람이 해도 되지만, 표본 다시 보기에는 두 번째 사람이 필요하다.** 두 번째 사람은 같은 컴퓨터에서 화면 맨 위의 이름을 **자기 이름으로** 바꿔 보면 된다.
두 사람이 같은 칸을 누르면 먼저 누른 답이 남고, 뒤에 누른 사람의 화면이 «먼저 답했습니다»를 알리고 그 답을 들인다.

## 1. 과제를 정한다

```bash
python3 .claude/os/engine/scripts/incr_review.py tasks
```

요청이 과제를 가리키지 않고 과제가 둘 이상이면 한 번 묻는다(AskUserQuestion, 선택지는 `name`).

## 2. 운영에서 모은다 — «운영에서 N개 가져와 넣어줘»

프로필에 `incremental` 블록이 있는 과제만 된다(계약 «새 데이터 모으기»). 없으면 «이 과제는 운영에서 바로 모으도록 설정돼 있지 않습니다 —
개발자에게 부탁해 주세요»라고 말한다.

**시험 등록 상품(상품명에 «테스트 상품»·«구매금지» 등)은 저절로 빠진다 — 뺀 것이 있으면(`skippedNotForSale`) «시험 등록 상품 N건은 뺐습니다»라고 한 줄 알린다. 운영 DB에 붙기 전에 한 번 묻는다**(AskUserQuestion) — «운영 DB에서 <과제 이름> 새 상품을 몇 개 가져올까요? (읽기만 합니다)», 선택지 100(권장)·50·200.
요청에 수가 있으면 묻지 않고 그 수로 간다. 조회는 읽기 전용 `mysql-query` 스킬로만 한다 — 쓰기 옵션을 붙이지 않는다.

```bash
python3 .claude/os/engine/scripts/incr_collect.py sql --task <과제>                              # 조회문 → mysql-query ... query --json "<조회문>" > <scratchpad>/rows.json
python3 .claude/os/engine/scripts/incr_collect.py detail-sql --task <과제> --rows <scratchpad>/rows.json --limit <N>   # 상세가 필요한 과제만 → details.json (고를 수의 3배를 읽는다 — 30초를 넘으면 플랫폼마다 따로)
python3 .claude/os/engine/scripts/incr_collect.py detail-mongo --task <과제> --rows <scratchpad>/rows.json --limit <N>   # ledgerFallbackPlatforms가 있는 과제만 → mongo-query aggregate seller_product_images → mongo.json
python3 .claude/os/engine/scripts/incr_collect.py build --task <과제> --rows <scratchpad>/rows.json [--details <scratchpad>/details.json] [--mongo-images <scratchpad>/mongo.json] --name <이름> --limit <N> --push
```

사진을 받느라 몇 분 걸린다 — 시작할 때 «사진을 받는 중입니다(몇 분)»라고 한 번 말한다.
결과는 이렇게 전한다 — «새 상품 W건을 넣었습니다. 사진을 못 받은 F건은 뺐습니다. AI가 지금 읽기 시작했고 몇 분 뒤 화면에 제안이 뜹니다.»
(`aiStarted`가 거짓이면 뒤 문장 대신 «다른 AI 작업이 끝나면 화면 위의 «AI 추론 시작»을 눌러 주세요».) 그다음 화면을 연다(§3).

## 2-1. 파일로 밀어넣는다 — «증분 넣어줘»

파일은 JSONL, 한 줄이 한 건이고 과제의 키 열(`keyField`)이 있어야 한다. 사진이 과제의 사진 색인(`gtTask.images`)에 아직 없으면
같은 모양의 증분 전용 색인을 `--images`로 함께 넣는다.

```bash
python3 .claude/os/engine/scripts/incr_review.py push --task <과제> --file <증분.jsonl> [--images <사진 색인.jsonl>] [--name <이름>]
```

- 거절(`ok: false`)이면 멈추고 «막혔을 때»의 문장으로 말한다 — 키 없음·키 겹침은 파일을 가진 쪽이 고친다.
- 성공하면 AI 추론이 뒤에서 이미 떠 있다(`aiStarted`). 거짓이면 «다른 AI 작업이 끝나면 화면의 «AI 추론 시작»을 눌러 주세요»라고 한다.
- `answerColumnsAlreadyFilled`가 비어 있지 않으면 «파일에 이미 답이 적힌 열이 있습니다 — 결과 파일이 그 열을 검수한 값으로 덮습니다»라고 알린다.
  `rowsLookLikeTests`가 비어 있지 않으면 «시험 등록 상품처럼 보이는 N건이 있습니다 — 파일을 준 쪽에 확인해 주세요(빼지는 않았습니다)»라고 알린다.
  `rowsWithPhotos`가 `rows`보다 작으면 «사진을 못 찾은 건이 있습니다 — 그 건은 AI가 읽지 못합니다»라고 알린다.

## 3. 화면을 연다 — 검수는 사람이 한다

서버를 켜고(`./serve.sh start`) `http://127.0.0.1:7391` + 결과의 `screen`을 크롬으로 연 뒤 이렇게만 안내한다.

> 화면 위에 이름을 적고 시작하세요. AI가 확신한 칸은 파란 테두리로 제안돼 있어, 맞으면 «AI 제안 N칸 확정» 한 번이면 됩니다.
> AI가 확신하지 못했거나 사람에게 물은 칸은 한 번에 확정되지 않으니 값을 직접 골라 주세요. 모를 때는 «보류»도 답입니다.
> 한 묶음을 다 보면 «다음 후보 받기 →»를 누르세요. 끝나면 «반영하기»를 누르면 결과 파일이 만들어집니다.
> «표본 다시 보기»는 한 번에 확정한 칸 가운데 일부를 **확정한 분이 아닌 다른 분이** 앞 답과 AI 제안을 가린 채 다시 고르는 자리입니다.
> 같으면 확인되고, 다르면 **«두 분의 답이 갈렸습니다»**로 남아 두 분이 아닌 세 번째 분이 골라야 확정됩니다. 표본을 다 봐야 «반영하기»가 됩니다. 다르게 나온 건이 있으면 표본이 늘어납니다.
> 버튼 둘은 하는 일이 다릅니다 — «AI 추론 시작»은 **이 묶음**을 AI가 처음 읽게 하고, «다음 후보 받기 →»는 **다음 묶음**으로 갑니다.

**AI 제안을 대신 확정하지 않는다** — 원장에는 사람이 누르거나 말로 명시한 판정만 간다(CLAUDE.md 규칙 5와 같은 선).
말로 판정을 받으면(«N1은 빨강이야») 누가 말했는지(`--reviewer`)와 **그 사람이 본 AI 제안**(`--expect-ai`, AI 제안이 없던 칸은
`--expect-ai-empty`)을 함께 적는다 — 먼저 `status`나 화면으로 그 칸의 AI 제안을 확인한다. 보류는 `--value` 대신 `--hold`:

```bash
python3 .claude/os/engine/scripts/incr_review.py record --task <과제> --batch <묶음> --key <키> --field <필드> --value <코드> --reviewer <이름> --expect-ai <본 AI 값>
```

AI가 사람에게 물은 칸은 가장 어려운 칸이라 **전부** 다른 사람이 한 번 더 본다(«표본 다시 보기»에 함께 오른다). 두 사람의 답이 같거나 세 번째 분이 가른 답만
골든셋 검수의 **사례**(사람이 답한 AI의 물음)로 모여 다음 판독에 간다 — 한 사람의 판단이 곧 사례가 되지 않게. 따로 옮기지 않는다.
시험 등록 건으로 보이는 상품은 한 번에 확정되지 않는다 — 검수할 데이터가 아니면 «보류»로 둔다.

## 4. 남은 것·다시 읽기·결과

```bash
python3 .claude/os/engine/scripts/incr_review.py status --task <과제> [--batch <묶음>]
python3 .claude/os/engine/scripts/incr_review.py run --task <과제> --batch <묶음> --reread   # 못 읽은 건만 (화면의 «다시 읽기»와 같다)
python3 .claude/os/engine/scripts/incr_review.py run --task <과제> --batch <묶음>            # 정책을 고친 뒤 — 확정하지 않은 건을 처음부터 다시 읽는다
python3 .claude/os/engine/scripts/incr_review.py export --task <과제> --batch <묶음>          # 모든 칸을 확정한 줄만 라벨을 채워 쓴다(화면의 «반영하기»)
```

수는 `status`가 센 그대로 전한다(규칙 8 — 다시 세지 않는다). «얼마나 남았어»에는 «답할 칸 N · 다시 볼 표본 M · AI가 못 읽은 건 K»로, 0인 수는 빼고 말한다.
결과 파일은 경로를 읽어 주지 않고 `open -R <경로>`로 Finder에서 보여 준 뒤 «방금 연 폴더의 파일»이라고 부른다.

## «증분 되돌려줘»

증분의 결과 파일은 원장의 **파생물**이라 원본을 바꾸지 않는다 — 되돌릴 원본이 없다.
- 결과 파일이 잘못됐다 → 답을 고친 뒤 «반영하기»를 다시 누르면 새로 만들어진다.
- 답 하나가 틀렸다 → 화면에서 그 칸의 «바꾸기»로 새 답을 고른다(다른 사람이 먼저 답한 칸이면 화면이 알리고 그 답을 들인다). 전 답은 지워지지 않고 «바뀐 답»으로 남는다(원장은 덧붙이기만 한다).
- 묶음을 통째로 잘못 넣었다 → 지우지 않는다. «그 묶음은 그대로 두고 답하지 않으면 결과에 나가지 않습니다 — 지워야 하면 개발자에게 부탁해 주세요»라고 말한다.

## 막혔을 때 — 사람에게 할 말과 다음 행동

| 보인 것 | 사람에게 할 말 | 다음 행동 |
|---|---|---|
| 운영 DB 연결 거절·시간 초과 | «운영 DB 로그인이 끝난 것 같습니다 — QueryPie 앱을 열어 다시 로그인한 뒤 «다시 해줘»라고 해 주세요.» | 멈춘다. 쓰기 옵션으로 바꿔 보지 않는다 |
| 조회가 30초를 넘김 | (말하지 않는다) | `--per-platform`을 절반으로 줄여 한 번 더 |
| 사진 받기 실패가 절반 넘음 | «사진 서버가 응답하지 않는 것 같습니다 — 잠시 뒤 다시 해 보겠습니다.» | 넣지 않고 멈춘다 |
| AI가 시작하지 않음(로그인 없음) | «이 컴퓨터의 Claude 구독 로그인이 필요합니다 — Claude 앱에서 로그인돼 있는지 봐 주세요. 로그인돼 있는데도 안 되면 담당 개발자에게 «AI 러너 로그인»을 부탁해 주세요.» | 멈춘다 |
| «이미 AI가 검수중» | «골든셋 검수의 AI가 먼저 돌고 있습니다 — AI는 한 번에 하나만 돕니다. 끝나면 화면 위의 «AI 추론 시작»을 눌러 주세요(이 묶음을 이미 다 읽었다면 «다음 후보 받기 →»).» | 기다린다. 잠금을 지우지 않는다 |
| 화면이 «서버가 꺼져 있습니다» | «화면 서버를 다시 켰습니다 — 새로고침해 주세요.» | `./serve.sh restart` |
| «반영하기»가 «표본 N건을 아직 다른 사람이 다시 보지 않았습니다» | «표본 다시 보기를 다른 분이 끝내야 결과 파일이 나옵니다 — 화면의 «표본 다시 보기로 가기»를 눌러 다른 분께 부탁해 주세요.» | 기다린다. 사람이 «<과제> 표본 없이 반영해줘»처럼 **다시 볼 사람이 없다고 말하면**만 `export --skip-recheck`를 돌리고 «표본을 건너뛰고 반영했습니다 — 그 사실이 결과 파일에 남습니다»라고 전한다 |
| 화면이 «두 분의 답이 갈렸습니다»인데 세 번째 분이 없다 | «갈린 칸이 있는 상품만 결과에서 빠지고 나머지는 반영됩니다. 그 상품은 갈린 두 분이 아닌 분(팀 리드 등)께 골라 달라고 하시거나, 모르면 «보류»로 두셔도 됩니다 — 리드가 갈린 두 분 가운데 한 분이면 보류로 둡니다.» | 갈린 칸은 확정으로 세지 않아 그 줄만 결과에 안 나간다(묶음 전체를 막지 않는다). `--skip-recheck`도 갈림은 풀지 않는다 |
| 키 없음·키 겹침(넣기 거절) | «파일의 N번째 줄에 상품 키가 없습니다(또는 이미 넣은 상품입니다) — 파일을 준 쪽에 고쳐 달라고 해 주세요.» | 멈춘다 |
| 그 밖의 오류 | «생각지 못한 문제로 멈췄습니다 — 개발자에게 이 대화를 보여 주세요.» | 오류 원문은 말하지 않는다 |
